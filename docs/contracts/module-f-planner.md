# Контракт Module F

## Модуль

`Module F: Planner`

## Назначение

`Module F` — самостоятельный модуль ручного календарного планирования графика КРС.

В UI он должен быть представлен как отдельный раздел sidebar:

- `Планировщик КРС`

Этот раздел не является частью сценарного раздела `Исходные данные` и не должен смешиваться с листом `Загрузка`.

## Входы

- `KrsScheduleScenario` из `Module D`
- `ImportedKrsSchedulePayload` из `Module A`
- planner commands / UI edits пользователя

## Выходы

- `PlannerScheduleRevision`
- planner-side schedule versions
- manual schedule revisions, готовые к передаче в `Module G`
- событие создания planner-версии, пригодное для автоматического формирования новой версии сценария в `Module G`

## Зона ответственности

- визуализация графика КРС
- хранение editable schedule representation
- версионирование графиков planner
- drag-and-drop и ручной перенос мероприятий
- сохранение planner revisions

## Не входит

- физический расчёт добычи
- экономика
- оптимизация графика
- принятие решения о новом сценарии расчёта

## Зависимости

- получает построенный график из `Module D`
- получает внешний готовый график КРС, нормализованный в `Module A`
- предоставляет `PlannerScheduleRevision` для прямого чтения `Module B` при planner-side recalculation
- передаёт planner revisions в `Module G`
- передаёт в `Module G` факт выполнения действия `Создать версию` вместе с `PlannerScheduleRevision` и ссылкой на активный сценарный контекст

## Контрактные правила

1. `Module F` владеет ручной календарной моделью графика.
2. `Module F` не пересчитывает добычу и экономику сам.
3. Любая ручная правка сохраняется как revision, а не затирает исходный schedule.
4. `Module F` должен уметь открывать график КРС как из `Module D`, так и из внешнего `ImportedKrsSchedulePayload`, подготовленного `Module A`.
5. Действие `Создать версию` в `Planner` должно создавать новый `PlannerScheduleRevision` и передавать его в `Module G` как основание для автоматического формирования новой версии сценария.
6. `Module F` не определяет состав сценарных атрибутов и не ведёт список сценариев; эти обязанности остаются в `Module G`.

## Важно

Старый смысл `Module F` как "planner bridge + feedback loop" больше не используется.  
`Planner` теперь выделен в отдельный модуль, а orchestration и пересчёт вынесены в `Module G`.
